# Authentic UI inventory — RECRUIT4US product screenshots

Real screenshots of the RECRUIT4US app (this repo), captured on 2026-09-30 with Playwright against a private local dev instance (PGlite, synthetic Northstar Labs demo). Nothing was mocked or drawn.

## How they were captured

- **Account:** a dedicated neutral capture account, **Equipo Demo / demo.recruiter@example.com**, created through the app's normal email sign-up. The Northstar demo was opened from that account, so every “signed-in user” record (sidebar, own candidate, portal header, offer) shows only this neutral identity. No real person's name or email appears.
- **Data:** only the seeded synthetic Northstar data (names such as Priya Raman or Marcus Hale, emails `@northstar.example`) plus a few synthetic records created through the product's own UI for this capture: 3 prospects, 1 referral and 1 campaign (`@example.com`), 18 built-in coding questions imported, one coding exercise sent, one live room opened, one self-schedule link, the integrity policy saved plus one similarity comparison, the fictional Data Analyst offer accepted, one pending hire opened, and one deletion request.
- **Viewport:** 1440×900 CSS px at deviceScaleFactor 2, light theme (the default), no browser chrome or URL bar. `scorecard` is an element capture of the interview card, `live-room` is cropped to the editor column, `careers-job` is cropped above the apply form, and `integrity` uses a 980 px tall viewport.
- **Output:** WebP quality 82. The main file is at most 2400 px wide and `-sm` is 1200 px wide.

### Redactions and edits applied before capture (display only; no data or source changed)

- The floating English/Español language pill is hidden so it doesn't cover the sidebar. Spanish UI is available in the product.
- Internal application IDs (24-hex) are removed from headings and replaced with `••••••` where they are part of a sentence (onboarding row). These IDs double as legacy portal unlock codes. Any input holding an ID is blanked.
- Lines showing invite or token links (“Candidate invite: /assess/…”, “Candidate path: /book/…”) are hidden, and any remaining UUID or token is masked.
- Nothing was captured from the URL bar. The company slug (which contains part of the account id) is not visible in any image.

## Deliberately not captured / caveats

- **Reviews → Code ranking** (`/app/$companySlug/reviews`) was captured but not exported. In the seed data every ranked answer shows “0 of 5 cases passed” (no judge ran), which is accurate but would read badly out of context.
- **Code judge results:** sample and final runs in this sandbox return “The judge could not run. This is not a score of zero.” (no `unshare` / Judge0 access here). The code screen was captured before running, so no result is pictured. Don't caption it with pass/fail results.
- **Live “watch exam in progress” views, the live-room tab/clipboard signal panel, proctored/camera exam screens, Connectors, Audit and Inbox (OTP codes):** excluded on purpose, per `northstar-demo-safety.md`. The captured mini-test attempt was not proctored and shows no camera UI.
- **Portal OTP unlock (`/portal`) and `/assess/$token` unlock screen:** not exported. They are forms that invite entering codes and add little visually. `/candidate` is used as the portal view.
- **Onboarding quirk:** after a full page reload the Hiring → Onboarding section showed “No pending hires”, even though “Open pending hire” returned the hire and its task list. The image shows the state the app renders right after the recruiter clicks “Open pending hire”. This looks like a product bug worth checking before claiming persistent onboarding lists.
- **Integrity case:** the similarity case was created by comparing two runs of the same demo submission (hence “Similarity 100”). The caption only claims what's on screen: a case that a person reviews.
- UI copy is English (the default locale). Captions are Spanish. Scorecard labels on screen are “Definite no / No / Yes / Strong yes”.
- Captions were checked against the forbidden-claims list in `marketing-claims.md`: no AI, auto-rejection, camera/proctoring, video hosting, LinkedIn, calendar sync or e-signature claims.
